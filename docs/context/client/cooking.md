# client: cooking

The Cooking panel (cooking plan PR 10, `docs/context/cooking.md`), grown from the Alchemy panel (`client/alchemy.md`): opened by the Cook ability, a moving panel where the player places kitchen tools in a grid of two rows (a step can join both), puts carried food, water, milk and honey into each step's drop spaces (and an intermediate at the start of a row, a culture for what ferments), sees what one run makes at the kitchen they are at, and starts it. Its Recipes tab (recipes plan PR 5, `docs/context/recipes.md`) lists the recipe book with Read, Make (the recipe laid on the grid, filled from what is carried, what is missing as red ghosts) and Remove. Also the recipe reading panel (recipes plan PR 4): one recipe from the book on an unrolled scroll. Every figure comes from `shared::cooking` (`Inventory::check_cooking`, `plan`), the server's own rules. Native and web.

## Public API

- `CookingPlugin`.
- `OpenCooking` (message): opens the panel, or closes it if open (`abilities`, on using Cook).
- `ReadRecipe(recipe::Entry)` (message): opens the reading panel on that recipe, or shows it there if open (the Recipes tab's Read). Reading a scroll opens it by itself (`RecipeInserted`).

## Notes

- Claude's choices (for the owner to tune) are in `docs/context/cooking.md`'s "The panel". Everything works by touch: taps are clicks, and a finger drags tools and steps; items are lifted by a finger resting on them, as the Inventory does everywhere.
- The kitchen is the client's guess at the server's: a campfire counts while one is drawn on the cell (the server also checks it is still lit), a hearth only once its tools are told. The order names the hearth only when one is faced; the server checks again before every run.
- Steps are sent and filled by column then row (`in_order`), so `run_seconds`' order and the fill agree.
- Ids: `cooking/tool.<Tool index>`, `cooking/step.<n>`, `cooking/place.<column × 10 + row>`, `cooking/source.<row>`, `cooking/food.<step × 100 + n>`, `cooking/liquid.<step × 100 + n>`, `cooking/faced.<step>`, `cooking/culture.0`, `cooking/ghost.<step × 100 + n>`; the Recipes tab's rows `cooking/read.<n>`, `make.<n>`, `remove.<n>` by the entry's place in the book. `client.cooking` also answers each step's ghosts, `wanted_sources` and `missing`. A canvas's id must not share a name with ids drawn inside it (`bind_panel` matches by name: `culture_space`, not `culture`).
