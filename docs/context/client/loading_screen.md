# client: loading_screen

The screen covering everything from the first frame until the game can take input: "Hall of Worlds" and, at the bottom, a bar saying what is happening. It comes back while the connection is lost, and shows why if the server refuses or the client won't trust it. At the startup menu (`common::Session::AtStart`) it is only the title, smaller and at the top, with the system menu over it.

## Files

- `crates/client/src/loading_screen/mod.rs`: `LoadingScreenPlugin`; `next_step` (from frames run and frames since the welcome), `title_font_size`, `bar_shows`, `take_all_input` (`PreUpdate`, before the widgets: clears keys, mouse, wheel and fingers while up, but not at the startup menu, which takes them, nor while `common::MakingCharacter`, `common::CharacterSelect::open` or `common::LoggingIn::shows`, whose screens take them), `LOADING` (the screen as markup: `loading/screen` holding the `loading/title` canvas and the `loading/bar` progress bar, class `loading`), `spawn_screen` (the document, on its own dark node over everything), `bind_screen` (`PostUpdate`, straight after the document is built and before layout, so in the first frame: the title in its font, already its size, and the bar's words marked for their colour), `show_screen` (through `Dom`: the bar hidden at the startup menu, while making a character and while logging in; its words and how full it is), `fit_title` (size and place by window and `Session`), Unit tests. `frames.rs`: `keep_frame_rate`. `page.rs` (web only): the page's own screen (`mark`, `starting`, `mark_first_frame`, `remove_page_screen`) and `show_stage` (`Last`: `stage.rs`'s word on `<html data-how-stage>`, only when it changes). `stage.rs` (web and tests): `stage_word`, where the game is as a word for the page's memory log: `menu`, `login`, `select`, `create`, `connecting`, `worldmap`, `hall`, `inn`, `wild`, `site:<poi kind in lower case>`; never a name or account. `screen.rs`: `LOADING`, `spawn_screen`, `bind_screen`, `title_node`. `marks.rs`: `StartupMarks` (added first and last in `main`, as plugins' `finish` and `cleanup` run in the order added: marks `how-finish-start`, `how-finish-done`, `how-cleanup-done` on the web, nothing natively); `marks/web.rs` (web only), the systems the last one adds: `how-startup-start` (`PreStartup`), `how-startup-done` (`PostStartup`), `how-first-render` (the render world's `PostCleanup`, once), and the first 120 frames' times (wall from `First` to the next `First`, the update, drawing from `ExtractCommands` to `PostCleanup`, pipelines made) in a thread-local both worlds share (one thread on the web), the 5 longest handed to `window.howLoading.frames` with their `LoadingStep`.
- `crates/client/src/loading_screen/takes_input.rs`: `takes_input`, when `take_all_input` runs (up after Play, but not while choosing or making a character or logging in).

## Public API

- `LoadingScreenPlugin`.
- `HoldLoadingScreen(bool)` (resource): keeps the screen up, for `HOW_DEBUG_LOADING_HOLD`.
- Web only: `page_starting()` (called first thing in `main`: the page says "Starting..." and marks `how-main`).
- `mark_page(name)` (`performance.mark` on the web, nothing natively): `main` marks `how-bevy-plugins`, `how-plugins-1` to `4` after each group and `how-app-built` before `app.run`.
- `StartupMarks` (plugin, `First` and `Last`): see Files.
- It writes `common::LoadingStep`, which is what others read.

## Depends on

- `common` (`LoadingStep`, `ServerStatus`, `GameView`, `TouchGesture`, `PointerSystems`, `frame_settings`, `KeepDrawing`, `Session`, `MakingCharacter`, `CharacterSelect`), `dom` (`Template`, `Dom`, `document`, `DrawObjects` for ordering), `dom` (`DomInput`, for ordering), `widgets` (`layer_z`, `UiId`).

## Used by

- `dev_tools` (`HoldLoadingScreen`). `connection` reads `common::LoadingStep`.

## Notes

- Its `GlobalZIndex` is just under the first full-screen layer (`widgets::layer_z(0) - 1`), above everything else, so the system menu's layers can be the startup menu over it.
- To add a step for startup work: add it to `LoadingStep`, then give it a place in `next_step` and words and a fill in `bar_shows`. The bar's positions are fixed for now, not timed.
- `connection` waits out `Starting`, or the word would never be seen: it would connect before the first frame is drawn.
- The title's font is built in with `include_bytes!` to be there on the first frame. `TITLE_EMS_WIDE` is measured from the font: change it with the font or the words. The font (`assets/fonts/HallOfWorldsTitle.ttf`) has only the title's letters: other words need it cut again (`ATTRIBUTION.md`).
- While up, frames keep their focused rate even out of focus (`common::frame_settings`), as they do afterwards too while `common::KeepDrawing` is on.
- On the web, `index.html` has its own copy of this screen saying "Downloading...", for until the wasm has loaded and started. Its bar is filled by `web/loader.js` (Trunk's initializer): "Downloading... N%" by the wasm's true size from the server (`/web/_wasm-size`; megabytes with no fill without it), then "Compiling...", then "Starting..." (from `page_starting`), filling at the pace of the last load's stage times (`localStorage` `how-loading-times`) and only as far as this bar's "Connecting..." (half), with a stripe sliding along it; all moving by transform, as the page's thread is busy while the game starts. It marks `how-download-start` and `how-download-done`, and `how-wasm-ready` when `main` returns; the game marks the rest (see `mark_page`, `StartupMarks`, `how-first-frame`, `how-page-screen-removed`). Once the screen is removed the page keeps the download, compile and start times, and once the game has also told its longest frames it logs `Loading times (ms)` in the console (`window.howLoading.measured()` any time): download, compile, start, total, `steps` (every `how-` mark from `how-main` on, in the order reached, as "a to b" ms) and `longest frames`. What they showed: `docs/context/optimisations.md`. `remove_page_screen` removes it when `Starting` ends, so there is no gap. Its colours, sizes and words are copied: change them in both places. `#ended` in the same page is the same screen for after quitting (`system_menu`). Its fonts come from the same server as the page, and its title stays hidden until its font has loaded.
- The memory log: `web/memlog.js` (copied by Trunk, loaded first in `index.html`'s head, doing nothing without `?memlog` in the address) wraps `WebGL2RenderingContext`'s texture, buffer, renderbuffer, program and shader calls (sizes by what is bound, kept by object), catches the wasm `Memory` through `WebAssembly.instantiate` and `instantiateStreaming`, and sends a JSON line a second by `sendBeacon` to the server's `/_memlog` (`HOW_DEBUG_MEMLOG`): `p` a random page id, `t` seconds since load, `s` the stage (`data-how-stage`: `web/loader.js` writes `download`, `compile` and `starting`, then `show_stage`), `wasm` MB, `tex`, `buf`, `rb` as [MB, count], `prog` alive, `links`, `shaders`, `new` and `del` that second, `canvas`, `dpr`, `js` (Chromium's heap), `ua` in the first line only, `ev` and `msg` on `pagehide` and errors.
